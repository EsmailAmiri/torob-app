# ترب همراه

دستیار خرید حضوری تهران با React، تم روشن/تاریک، بک‌اند TypeScript و LangGraph. نمونه مستقل چالش ترب است و به حساب یا API رسمی ترب متصل نیست.

## اجرای محلی

نیازمندی: Node.js نسخه 24.13 یا جدیدتر و Python 3 برای ساخت اولیه دیتابیس.

```sh
npm install
npm run db:seed
npm run dev
```

`npm run dev` در اولین اجرا هم می‌تواند دیتابیس را بسازد؛ فرانت روی پورت ۵۱۷۳ و API روی ۸۷۸۷ اجرا می‌شوند. Vite درخواست‌های `/api` را به Node می‌فرستد. بدون کلید مدل، ابزارهای داده و چت با برچسب صریح «حالت محلی» کار می‌کنند.

اجرای خروجی ساخته‌شده با Node:

```sh
npm run build:node
npm start
```

`dist/client` همراه API سرو می‌شود. پیش‌فرض Node فقط روی loopback گوش می‌دهد. اتصال عمومی مستقیم نیازمند `APP_ACCESS_TOKEN` و لایه احراز هویت مناسب است؛ میزبانی Sites از احراز هویت خود پلتفرم استفاده می‌کند.

## اتصال 9router

فایل `.env.example` را در `.env` کپی کنید و آدرس، کلید و مدل واقعی خود را فقط در بک‌اند تنظیم کنید:

```dotenv
LLM_PROVIDER=9router
LLM_API_KEY=
LLM_BASE_URL=http://127.0.0.1:20128/v1
LLM_MODEL=
LLM_API_STYLE=chat_completions
```

مدل باید tool calling را پشتیبانی کند. شناسه مدل/ترکیب باید دقیقاً با تنظیمات 9router خودتان تطبیق داشته باشد. سپس بک‌اند را دوباره اجرا کنید. در محیط منتشرشده، URL باید از سرور میزبان قابل دسترس باشد؛ `localhost` آن محیط رایانه شخصی شما نیست.

اتصال مستقیم OpenAI با `LLM_PROVIDER=openai` و `LLM_API_STYLE=responses` نیز پشتیبانی می‌شود. نام‌های قدیمی `OPENAI_API_KEY`، `OPENAI_MODEL`، `OPENAI_BASE_URL` و همچنین `NINEROUTER_KEY`، `NINEROUTER_URL` پذیرفته می‌شوند.

کلید در فرانت، Git، فایل hosting یا خروجی `/api/health` قرار نمی‌گیرد. `.env*`، دیتابیس اجرایی و داده‌های گفتگو در Git نادیده گرفته می‌شوند. روی Sites، متغیرها باید runtime secret باشند و پس از تنظیم، نسخه دوباره deploy شود. **اتصال واقعی 9router در محیط محلی آزموده شده است.** آدرس فعلی مدل محلی است و برای نسخه ابری باید endpoint قابل دسترس و secret همان محیط تنظیم شود.

## جریان دستیار

`server/agent.ts` یک StateGraph واقعی LangGraph دارد:

```text
درخواست → مدل → اجرای ابزار معتبر → مدل → پاسخ و تغییر رابط
            ↑                       |
            └───────────────────────┘
```

| ابزار               | کار                                          |
| ------------------- | -------------------------------------------- |
| `search_products`   | جست‌وجو، بودجه، برند و تغییر شرایط صفحه      |
| `compare_products`  | مقایسه مشخصات دو یا سه محصول واقعی           |
| `find_sellers`      | آفرهای دقیق محصول، فاصله، ساعت و پرداخت      |
| `get_shop_details`  | آدرس و اطلاعات فروشگاه بدون شماره‌های جعلی   |
| `request_inquiry`   | ایجاد استعلام آزمایشی؛ هیچ تماسی نمی‌گیرد    |
| `find_alternatives` | آفرهای دیگر و محصولات هم‌دسته با رعایت بودجه |
| `suggest_market_areas` | بررسی دوباره دیتاست و پیشنهاد ناحیه خرید با منبع، نقشه و مسیریابی |

پارامترها با Zod اعتبارسنجی می‌شوند؛ مدل به اجرای SQL یا کد دلخواه دسترسی ندارد. پس از هر مرحله مدل/ابزار، وضعیت در دیتابیس ذخیره می‌شود. تلاش دوباره با همان request ID ادامه می‌یابد و ابزار موفق قبلی دوباره اجرا نمی‌شود. شش نوبت اخیر با جفت‌های کامل فراخوانی/نتیجه ابزار نگه داشته می‌شوند. پاسخ کامل به request ID تکراری از وضعیت ذخیره‌شده خوانده می‌شود.

گفتگو به مالک و UUID متصل است. قفل دیتابیس جلوی دو نوبت هم‌زمان را می‌گیرد. تعداد پیام، گام‌های مدل، اندازه ورودی و زمان پاسخ محدود است. رابط وضعیت پردازش، نتیجه ابزار، خطا و تلاش دوباره را نمایش می‌دهد. شروع گفتگوی تازه از نمایش پاسخ دیررس قبلی جلوگیری می‌کند.

## داده

هر **۲۲۵٬۹۰۳ محصول، ۶٬۴۷۶ فروشگاه و ۳۳۱٬۵۰۶ آفر** حفظ شده‌اند. داده‌های فشرده در `public/data` هستند. بازسازی از ZIP پوشه بالاتر:

```sh
npm run data
```

SQLite محلی در `runtime/torob.sqlite` ساخته می‌شود. FTS5 با یکسان‌سازی نویسه‌ها و اعداد فارسی/عربی، جست‌وجوی سمت سرور، فیلتر بودجه و مرتب‌سازی را اجرا می‌کند. هنگام آماده بودن API، مرورگر ایندکس بزرگ جست‌وجو را دریافت نمی‌کند. Web Worker به عنوان fallback نبود دیتابیس کامل روی میزبان باقی است.

در Sites، D1 ایندکس، فروشگاه‌ها و گفتگوها را نگه می‌دارد؛ فایل‌های کامل کاتالوگ در R2 همان سایت ذخیره و با checksum منتقل می‌شوند. مشخصات و آفرها هنگام نیاز از بخش متناظر R2 خوانده می‌شوند تا داده حجیم در SQL تکثیر نشود. بسته انتشار فقط کد، رابط و داده‌های کوچک اولیه را دارد؛ فایل‌های اصلی در سورس محلی و مخزن حفظ شده‌اند.

## رابط

- ظاهر آشنای ترب، فارسی و راست‌به‌چپ و مناسب موبایل.
- تم روشن، تاریک و سیستم؛ تغییر سریع از سربرگ و انتخاب سه‌حالته در «درباره این نسخه». انتخاب ذخیره و پیش از نمایش صفحه اعمال می‌شود.
- مقایسه حداکثر سه محصول، علاقه‌مندی محلی، فروشندگان نزدیک و فیلتر شرایط مراجعه.
- Leaflet و OpenStreetMap؛ انتخاب محله یا موقعیت فعلی و مسیریابی Google Maps.
- جابه‌جایی مبدأ خرید با لمس نقشه؛ رتبه‌بندی فروشندگان و فاصله‌ها فوراً با مبدأ تازه محاسبه می‌شوند.
- کارت راهنمای مراجعه، نزدیک‌ترین فروشندهٔ طبق برنامه باز را با فیلتر بودجه و اقساط حضوری پیدا می‌کند؛ اگر بیرون شعاع باشد، امکان گسترش شعاع می‌دهد. ساعت نامشخص و محدودهٔ خرید بیرون دیتاست با منشأ و عدم قطعیت جدا نمایش داده می‌شوند.
- ناحیه‌های خرید مستند برای دیجیتال، دوربین، ورزشی، کتاب و لوازم خانگی؛ لینک منبع در کارت جدا و بدون ادعای موجودی یا قیمت همان محصول نمایش داده می‌شود.
- آدرس پاساژ/طبقه/واحد در صورت وجود به شکل راهنمای داخل ساختمان از متن همان آدرس استخراج می‌شود؛ مسیر داخلی ساخته یا حدس زده نمی‌شود. ساعت کاری به زمان تهران با پشتیبانی از شیفت شبانه خوانده می‌شود.
- پاسخ‌های آزمایشی موجودی/عدم پاسخ در بک‌اند ذخیره می‌شوند و تأیید واقعی موجودی محسوب نمی‌شوند.

## API

| مسیر                               | کاربرد                                                    |
| ---------------------------------- | --------------------------------------------------------- |
| `GET /api/health`                  | آمادگی کاتالوگ و مدل، بدون اسرار                          |
| `GET /api/products?query=...`      | جست‌وجو؛ brand، budget، sort، limit، offset               |
| `GET /api/products/:id`            | مشخصات و آفرهای دقیق محصول                                |
| `POST /api/compare`                | مقایسه شناسه‌های محصول                                    |
| `POST /api/sellers`                | فروشندگان با شرایط محدوده                                 |
| `POST /api/chat`                   | اجرای LangGraph با threadId، requestId، message و context |
| `GET /api/chat/:id`                | بازیابی پیام‌های همان مالک                                |
| `POST /api/inquiries`              | ایجاد استعلام آزمایشی                                     |
| `POST /api/inquiries/:id/simulate` | ثبت پاسخ فرضی صریح                                        |

مسیرهای `POST /api/admin/assets` و `POST /api/admin/import` فقط برای bootstrap نسخه خصوصی Sites هستند. به `CATALOG_IMPORT_ENABLED=true` نیاز دارند؛ ابتدا فایل‌های gzip با نام معتبر و checksum به R2 فرستاده می‌شوند و سپس بخش `shops` یا `00` تا `ff` وارد D1 می‌شود. اسکریپت `scripts/import-hosted.mjs` با توکن سرویس از stdin مخفی این کار را انجام می‌دهد و امکان تلاش دوباره دارد. پس از کامل‌شدن کاتالوگ، نوشتن دوباره متوقف می‌شود. این مسیرها را بدون احراز هویت پلتفرم عمومی نکنید.

## انتشار و migration

`npm run build` خروجی Worker و React را در `dist/server` و `dist/client` تولید می‌کند و integration رسمی `sites()` حفظ شده است. همان شناسه Site و audience خصوصی قبلی استفاده می‌شوند. binding دیتابیس D1 با نام `DB` و ذخیره‌ساز R2 با نام `BUCKET` در `.openai/hosting.json` است. Node و Worker از API و repository مشترک استفاده می‌کنند. `npm run build:node` همچنان تمام فایل‌های دیتاست را برای اجرای محلی در خروجی نگه می‌دارد.

اسکیما در `db/schema.ts` و migration در `drizzle` است؛ FTS5 و triggerها در SQL اولیه ثبت شده‌اند. migration اعمال‌شده را تغییر ندهید. برای تغییر بعدی، schema را ویرایش، `npm run db:generate` اجرا و migration جدید را بررسی کنید. seed دیتاست از migration جداست. `npm run db:seed`، migrationهای جدید محلی و سپس ورود داده را انجام می‌دهد.

## بررسی

```sh
npm test
npm run typecheck
npm run build
```

آزمون‌ها جست‌وجوی واقعی SQLite، فیلتر قیمت، مالکیت و قفل گفتگو، LangGraph، request ID تکراری، ادامه پس از خطای مدل، قرارداد 9router، عدم افشای کلید، کنترل مبدأ و استعلام آزمایشی را پوشش می‌دهند. آزمون‌های زمان تهران، شیفت شبانه، پردازش فارسی، تصمیم مراجعه و محدود کردن نام ناحیه‌های بیرونی به خروجی ابزار حفظ شده‌اند. تم دارک، ماندگاری آن، مقایسه، نقشه، استعلام، فروشندگان و عدم اسکرول افقی در عرض‌های ۱۴۴۰ و ۳۹۰ در مرورگر بررسی شده‌اند.

## محدودیت‌ها

تماس واقعی یا تأیید موجودی انجام نمی‌شود؛ شماره‌ها و بیشتر نام‌های دیتاست جعلی‌اند. آفر تاریخی با قیمت امروز یکی نیست. ساعت کاری اعلام‌شده و فاصله مستقیم است. بانک ناحیه خرید بیرونی پنج دسته را پوشش می‌دهد و جستجوی زنده سراسر وب نیست؛ سرویس عمومی مکان برای مسیر اصلی خرید به اندازه کافی پایدار نبود. علاقه‌مندی‌ها دستگاه‌محلی‌اند. پاسخ گفتگو فعلاً یک‌جا نمایش داده می‌شود و streaming توکن‌ها پیاده نشده است. گزارش آزمون و محدودیت‌های تحویل در [CHALLENGE-TEST-REPORT.md](CHALLENGE-TEST-REPORT.md) است؛ ویدئوی دمو الزامی باید جداگانه تهیه شود.
